# Quirks of version 1.3 and how version 2.0 treats them

This page registers every quirk, bug and inconsistency that the study of version 1.3 found, and
says what version 2.0 does with each of them. Version 1.3 is 3D-Baukasten, the program in Visual
Basic 5 that Herbert Kleber wrote in 2002, with the C library `graf3d32.dll` and the diploma thesis
"Grundlagen der 3D-Computergrafik". Version 2.0 is the rewrite in Rust, WebAssembly and WebGPU by
Florian Kleber in the same repository. The files of version 1.3 stay unchanged at the root of the
repository, so every entry describes them as they are, and version 2.0 decides per entry. The last
section registers the issues of the rewrite itself.

Each table has five columns. The column ID names where the entry comes from:

| Prefix | Source |
| --- | --- |
| `Q-n` | Quirk n of the notes on the main window Form1, the bars F2, F3 and F5, the slide show F9, the splash and the modules as Form1 uses them, numbered 1 to 112 |
| `F4-Qn` | Quirk n of the notes on the register form F4 "Eingaben", numbered 1 to 100 |
| `M-n` | Quirk n of the notes on `Module1.bas`, `Module2.bas`, `POV.bas`, `graf3d32.dll`, the binaries and the assets, numbered 1 to 80 |
| `T-pn` | An inconsistency of the thesis on page n of its PDF, inside its text or between text, screenshots and code. A letter tells several entries of one page apart, and `T-p0` stands for the PDF as a whole |
| `C-n` | Entry n of the list of deviations in the plan of the classic look of 2.0 |
| `R-n` | Issue n of the rewrite, a decision about version 2.0 itself or a limit of the platform it runs on. Up to 46 the number is that of the resolution in the master plan of 2.0, and from 47 on it names an issue the plan records under another name |

An entry that names several IDs merges findings that describe the same thing. The column
"Version 1.3" says what the original does and names the file or the procedure. The column
"Version 2.0" says what the rewrite does. The status is one of four words:

- `Kept` means that version 2.0 behaves as version 1.3 does.
- `Fixed` means that version 1.3 has a defect and version 2.0 does not.
- `Changed on purpose` means that version 2.0 behaves differently by a decision, which the text
  gives.
- `Not applicable` means that version 2.0 has nothing the entry could apply to, such as a detail
  of Visual Basic, a file of version 1.3 or the PDF of the thesis, and the text says why.

The column Test names the check that proves the entry, as `nn:name`. The number `nn` begins the
name of a notebook under `tests/notebooks/`, and `name` is a tag of one code cell of that notebook,
kept in the metadata of the cell, where papermill finds its tag `parameters` as well. The tag
counts as proved when that cell of the executed copy under `tests/notebooks/out/` ran without an
error and printed a passed check whose message names one of the IDs of the entry. An entry with
several tags lists them separated by commas. A dash `–` stands for an entry that has nothing a
program could prove, such as a detail of Visual Basic, a file of version 1.3 or a page of the
thesis. Notebook 90 reads the column back, and a tag that no passed check proves fails it.

Version 2.0 has two looks over one page. The modern look is the default. The classic look shows the
windows of version 1.3 in the style of Windows 98 and changes presentation only, never data, and it
reproduces no bug. Where the modern look docks its panels and so has nothing the entry could apply
to, the status follows the classic look. Where both looks have the behaviour and differ, the status
names the modern look and the text says what the classic look keeps. A behaviour that the classic
look shows as version 1.3 does is a toggle with a name, the text of its entry names it, and R-47
lists all of them. Where the notes found a behaviour by reading the code and not by running
version 1.3, the entry says "derived".
